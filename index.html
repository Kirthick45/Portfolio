My Approach
How I Think
01

Start With the Question

Every analysis begins with "what decision does this data need to support?" I don't touch code until the business or research question is sharp.

02

EDA Is the Real Work

I spend 60% of my time on exploratory analysis. Distributions, outliers, correlations — I need to understand the data before I can say anything meaningful about it.

03

Engineer Signals, Not Just Features

Raw columns rarely tell the story. I build derived features — ratios, lags, crisis indicators, volatility windows — because that's where the signal lives.

04

Visualise to Think, Not to Decorate

Charts are how I verify my own hypotheses. If a plot doesn't change my understanding of the data, it doesn't belong in the analysis.

05

Ship It, Don't Sit On It

Analysis that stays in a notebook helps nobody. Everything I build gets deployed — Streamlit apps, GitHub repos, PDF reports — so others can actually use it.

06

Systems Thinking Scales

Building a CPU scheduler taught me that resource allocation is the same problem in OS, timetabling, and ML pipelines. Abstractions that generalize are worth learning.
